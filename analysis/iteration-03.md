# 第三轮：页内分组切换与纯封面书架

日期：2026-11-11（Asia/Shanghai）。当前运行时与生成安装包为 0.5.1。侧栏已安装的 0.2.0 启动包装通过本地开发更新加载本轮代码。

## 已确认需求

- 点击分组时消除整页跳变与旧界面闪回。
- 移除封面下方独立书名，只保留完整封面，改善可视区域。
- 继续采用小步实现、现场体验和反馈的迭代方式。

## 实现

- 通过原站 GET /web/shelf/sync?onlyBookid=1 与 GET /web/shelf/sync 读取索引、现有分组和封面、原站阅读链接。
- 只读元数据补充沿用原站 FETCH_SHELF_LOAD_MORE 对 POST /web/shelf/syncBook 的调用形态。本次补充请求未返回额外条目；未把缺失条目当成已删除。
- 分组按钮更新页面历史与当前封面视图，不再触发原生链接的整页跳转。缓存各组已加载的封面 DOM 与右侧滚动位置，左栏保持挂载。
- 首批显示 36 个封面，滚动接近末端再追加。完整封面按比例显示，不裁切；书名仅存在于悬停提示及无障碍名称中。
- 书籍阅读链接直接使用接口提供的 readerLink。公众号聚合入口缺少链接，依据已发布 URL codec（模块 156）构造其原站链接，编码与已观察的原生链接一致。
- 当前数据留在微信读书页面内；本机开发服务只提供脚本代码。

旧版原生路由尝试无法稳定避免重载；嵌入视图实验收到原站限制提示后已撤回。最终实现无 iframe，也不依赖 Vue 私有实例。

## 证据与验证

静态分析依据为 analysis/rea-initial 中已选定的原站脚本、REA 结果与模块提取记录；分析范围及限制沿用 FINDINGS.md。以下是本轮实际侧栏浏览器验证，而非仅靠静态推断：

- 从“沉浸式阅读”切换到“游戏设计”，增强实例标记保持 1794384070729-wrhqw4f00o，地址、右侧标题和 5 本封面一致；左栏筛选“设计”保留。
- 浏览器返回后恢复“沉浸式阅读”的 21 本封面，实例及筛选内容保持。
- 未分组滚动后由 36 个封面继续追加到 54 个。切换至其他组再返回，滚动位置仍为 1179.43px。
- 当前接口返回 1079 本书籍元数据，另保留 1 个公众号入口；21 个分组。未分组另有 3 条索引没有返回元数据，显示“3 项暂未返回”，不宣称所有元数据均已覆盖。
- 1043px 宽窗口显示五列完整封面，无横向溢出；加载完成的封面未发现失败图像。
- 四个数据模型测试通过：MD5 多块 UTF-8 输入、两类原生链接编码、分组与未分组整理及缺失状态、补充元数据及公众号入口去重。
- 生成文件经过 Node.js 语法检查。
