# 第六轮：开发流程简化与第一版发布

日期：2026-11-12（Asia/Shanghai）。发布版本 v1.0.0。

## 已确认

- 用户确认当前功能达到第一版预期，要求 Git 提交、开发／发布两个分支及版本 Tag。
- 默认通过对话提需求，助手按需使用 REA、修改并验证；用户在侧栏手动全文覆盖同一脚本体验。
- 自动预览保留，但默认关闭。

## 工程调整

- package.json 统一管理版本与 build／test／check／preview 命令，版本自动写入启动元数据和运行时。
- 默认构建不读取端口文件，不依赖本机服务；正式文件没有 GM_xmlhttpRequest、127.0.0.1 连接或开发轮询，直接复制 src/weread-shelf.user.js 更新。
- 可选更新器拆到 development-updater.js，只在显式开发构建中包含；还需 rea-dev=1 启用，rea-dev=0 可关闭。
- 可选预览服务启动时自动生成开发文件，并按请求组装最新预览。正式文件保持独立，不被预览输出覆盖。
- README 改为默认手动更新的短流程，AGENTS.md 固定协作约定，CHANGELOG.md 记录首版功能与边界。
- 未使用的旧版增强源码移到 analysis/archive，本机截图、捕获、原始分析大文件、临时端口和 ZIP 不进入 Git；摘要和迭代记录保留。
- Git 使用 release 保存发布基线，develop 用于后续开发，首版附注 Tag 为 v1.0.0。

## 验证

- npm run check 成功：独立构建、13 项测试、生成脚本语法检查全部通过。
- 构建测试验证正式文件无需服务状态且不含开发授权，早期注入的完整运行时可解析；开发版没有主动启用时不轮询，启用后只访问声明的本机地址，非本机地址被构建拒绝。
- 可选预览服务实际 HTTP 检查返回 200，版本为 1.0.0；POST 返回 405。测试进程结束后已停止，原有临时服务记录已恢复。
- 本轮未新增界面功能，沿用上一轮实际侧栏验证与用户“拖动成功”的确认。独立正式脚本仍需用户按默认方式复制到已安装脚本后使用；不能把旧安装的开发预览等同于已完成手动更新。

## 待确认

- 无影响本轮 Git 发布的待确认事项。后续体验问题继续由对话提出并在 develop 迭代。
